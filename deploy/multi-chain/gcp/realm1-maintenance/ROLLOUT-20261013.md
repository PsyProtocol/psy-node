## Process Correction

All scripts, review, binary/file preparation, and execution permissions must be
ready BEFORE closing admission or stopping the writer. Once the cutover starts,
there must not be a human authorization pause between stop and start. A closed
gate is itself user-visible downtime, even while queries remain available.

Future orchestration must have explicit bounded phases, operator-visible window
timers, and a tested recovery path. Do not automatically reopen to an unverified
writer or restart the old writer after the target may have written shared state.
The current run did not satisfy the intended minimal-interruption objective.

## Recovery Rules

- Before the target ever starts: source files remain unchanged and available;
  any rollback must explicitly restore its permit/lifecycle configuration.
- After target startup: never start the old writer with its stale local files.
  First fence/stop the new writer, preserve its latest checkpoint files, and
  reconcile/copy them back under a separately checked rollback procedure.
- A timeout is not proof of no target activation. Inspect PID, executable,
  startup permit and logs before taking another lifecycle action.
- Collector monitoring should be added on the target first after acceptance,
  then removed only for the old source Processor. Indexer/Edge probes stay put.
