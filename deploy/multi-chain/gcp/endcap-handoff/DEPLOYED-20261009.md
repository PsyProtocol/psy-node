## Tests and limits

- Independent staged review passed for the exact live backport, stable and
  deployment integration, and the installer.
- EndCap-targeted tests: 13/13 passed in debug and release, including rotations
  during verification/after publication, bounded restaging, competing submission,
  and planner deduplication of a copy after the first was included.
- Installer tests: 44/44 passed; full apply orchestration is not simulated by
  these offline tests, so live checks remain necessary.
- Expanded candidate debug and release suites: 161 passed, 6 failed, 2 long
  randomized tests excluded. All six failures were independently reproduced in
  debug on the exact unmodified `876c1432` baseline. They concern the Coordinator
  realm-capacity check and non-power-of-two registration-tree test assertions.
  This is not a claim of a fully passing suite. The colleague's separate long
  randomized test was not interrupted.
- A debug run that still included `check_many_and_print_errors` was terminated
  before rerunning with that long test excluded. The isolated candidate and
  baseline logs are in `tmp/endcap-handoff-live-20261009/` in the operator workspace.
- Production race injection was not performed. Observed ordinary transactions
  cannot prove the rare handoff race is impossible; deterministic tests cover it.
- Late gatherer arrivals after finalize, Processor silent `Ok(0)` on missing
  artifacts, and the historical 39 missing transactions remain separate work.

## Rollback

Private frozen package: `/opt/parth-endcap-package-20261009/`.
The manifest contains the pre-activation capture from 06:40:41 UTC, checkpoint
208170 on all three Edges. Recovery records and original binary copies are under
the immutable release's `rollback/realm-0` and `rollback/realm-1` directories.

Only the affected Realm is rolled back; do not remove older overrides:

```sh
ssh gcp-cp-ce 'sudo python3 /opt/parth-endcap-package-20261009/rollout.py rollback --unit realm-0'
ssh gcp-cp-ce 'sudo python3 /opt/parth-endcap-package-20261009/rollout.py rollback --unit realm-1'
```

The guards refuse recovery if protected configuration or unrelated PIDs have
changed. Investigate that drift rather than rewriting the baseline to bypass it.
The previous executable remains selected by `99-worker-reputation-20261008.conf`
after removal of this rollout's own override.
