## Provider policy

Provider declarations are ordered preferences; actual selection depends on
availability and recovery trials. Private URLs remain outside Git:

| Chain | Configured order |
| --- | --- |
| Ethereum Sepolia | Local HTTP node, colleague Alchemy, Peter Alchemy |
| BSC Testnet | Colleague Alchemy, Peter Alchemy |
| Base Sepolia | Colleague Alchemy, Peter Alchemy |

BSC/Base use separate subscriptions but the same infrastructure operator.
The corresponding startup warnings are expected; this is not cross-provider
infrastructure redundancy. Keep Relayer-only inputs separate from shared
Services/Envio/public RPC configuration. Config generation must preserve order,
names and operator/quota metadata; never commit actual subscription URLs.

The deployed source contains the RPC pool/transport change, not finalize state
reconciliation from `93dc14ad` or the separate BSC fee-policy candidate.
Documentation in the integration commits corrects the original mistaken claim
that reconciliation was included. An `already known` response is not settlement
confirmation. Proof generation and L2 operations are not replayed by the RPC pool.

## Verification and incident boundary

The deployment handoff reported 47 pool and 214 release-mode Relayer tests.
Fresh integration tests passed: stable 214 Relayer + 47 pool; `multi_chain`
215 Relayer + 47 pool. The provider-certification tool's self-test passed with
mock/loopback servers. These are not funded-transaction E2E or live forced
failover tests. Live executable/config hashes matched the values above.

At 09:05:54 and 09:06:54 UTC, all three L1 StateManagers reported finalized
checkpoint 197626. The service had PID 1897667 and zero restarts then; sampled
journals contained no `RPC provider attempt failed` lines. Existing L2 errors
`Key not found in IMT` and `Leaf preimage not found` were still observed, including
index 19214 at 09:05:49. This integration does not fix those errors.

A later check at 09:28:27 UTC found PID 1899493, `NRestarts=12`, and all three
L1 finalized checkpoints still 197626. Journals from 09:16-09:19 show startup
failures reaching the SYSTEM proxy's role endpoint. Both x1's local
`127.0.0.1:19998` and its WireGuard `10.250.0.13:9998` role requests timed out;
the x3 SYSTEM role endpoint responded correctly. The gateway still targeted x1.
No route was changed during this source integration. Thus `active` alone must
not be reported as healthy finalization, and this observation does not establish
an L1 provider-pool failure. Proxy recovery requires a separate operational action.

Never reset daemon state, queues, accounts, Genesis or proving setup to recover
this release. Preserve the per-component override and private backups. Any
future rollout/rollback must recheck current identity and configuration before
changing them; this document does not authorize that action.
